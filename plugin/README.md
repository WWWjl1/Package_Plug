## 当前形态：阶段一（动态 Cordis 插件）

这两份代码**不是 npm 包，也不是可以直接 import 的模块**。它们是 dsh「动态插件」的源码：

- 都是一段**函数体**，不是完整模块 —— 结尾 `return { ... }` 就是插件的定义
- 不能用 `import` / `require` / TypeScript / JSX
- 可用的全局符号只有：`ctx`、`React`、`host`、`styles`、`console`
- 界面代码只能写 `React.createElement(...)`，不能写 JSX

### 怎么装

在 dsh 里让 Agent 用 `cordis_define` 把这两份代码分别作为 `code.host` 和 `code.client` 传入，
再用 `cordis_run` 激活。首次激活浏览器端要你点一次「允许」。

**动态插件只活在当前 dsh 进程里**：dsh 一重启就没了，需要重新激活一次。

## 路线图：阶段二（常驻插件）

目标是把现在这份动态插件，改造成一个**装一次就一直在**的正式 web 插件包，让别人也能直接安装：

- 打包成带 `dsh.client` 声明的 npm 包（参考 `dsh-better-sidebar` 的形态）
- 挂到 profile 的 bundle 栈里，开机自动挂载
- 把下面这个写死的路径改成可配置项
- 顺手把界面按需再打磨

## 已知限制

1. **数据根目录写死在 `host.js` 顶部**：

   ```js
   const ROOT = 'D:/Dsh_WorkSpace/Package_Learn_Plug_In'
   ```

   别人 clone 这个仓库后，如果文件夹不叫这个名字、或者不在这个位置，
   **需要改这一行**。阶段二会把它变成可配置。

2. **学习界面里发送消息后的自动跳转**依赖 dsh 只发给「当前激活视图」的 `openView` 接口，
   所以只有在学习界面里发送才会触发跳转（在原生对话界面里发送本来就不需要跳）。

3. 现在只有「引线键合」一道工序有内容，其余是占位。
