# tools/ —— 验收脚本

这些脚本是**给我自己（和以后的你）用的**：改完插件或课程之后，跑一遍就知道有没有把东西弄坏。
它们不属于插件运行路径，删掉不影响插件工作。

## 一条命令跑完

```powershell
node tools/check-all.mjs
```

或者单独跑：

```powershell
node tools/check-content.mjs    # 课程内容
node tools/check-host.mjs       # 主机半
node tools/check-client.mjs     # 客户端半（静态接线 + CSS）
node tools/check-render.mjs     # 真渲染一遍界面
```

> 别用 `.ps1` 写这类脚本：Windows PowerShell 5.1 读 `.ps1` 默认按系统 ANSI 编码解码，
> 脚本里一有中文就变乱码、引号还会跟着断（第一版 runner 就是这么挂的）。
> Node 读文件一律 UTF-8，没有这个坑。

## 四个脚本各管什么

| 脚本 | 它真的会做什么 | 它抓什么 |
|---|---|---|
| `check-content.mjs` | 读全部内容 JSON，逐块校验结构、统计细分点/小测数、检查配图能不能打开 | 字段缺失 / 类型不对 / answer 越界 / 图找不到 / 正文里混进反引号或 Markdown 标题 |
| `check-host.mjs` | 用假 ctx **真的挂载主机半**，再走一遍 HTTP 路由调它的每个方法 | 挂载抛错、方法返回不对、课程自检报错、关联断链、导入导出的往返、来源限制、时长累加 |
| `check-client.mjs` | 静态读 `lib/client.js` | 关键接线是否还在（哪个按钮接了哪个函数）、导入/重置的**写入顺序**（必须先备份）、**CSS 同名选择器重复定义**、横排会不会溢出被裁、用到的类名有没有样式 |
| `check-render.mjs` | 把 `content/` 拷到临时目录，挂上主机半，再用自制迷你 React **把学习界面完整渲染一遍**，并点几下按钮 | 渲染时崩溃、数据字段不对、Hook 顺序变化、界面某块根本没渲染出来、点了没反应 |

## 它抓不到什么（别指望）

- **CSS 到底长什么样**：`check-client.mjs` 只能查「同名选择器被定义两次」这类静态问题；
  颜色、间距、真实浏览器里的重排与溢出，它看不见。所以每次改完 `client.js` 的样式，
  仍然需要有人在浏览器里看一眼。
- **视觉美观、交互手感**：渲染测试能确认「元素出来了」，不能确认「好看」。
- **嵌套错位的 SVG**：`check-content.mjs` 的配对检查只数开闭标签个数，
  `<a><b></a></b>` 这种它抓不到；要严格校验得用 XML 解析器。
- **真实 dsh 服务**：脚本用的是假 ctx / 假浏览器。dsh 升级改了服务名或槽位名，
  它照样全绿——那种情况要靠界面左下角那条挂载失败提示。

## 一些约定

- 脚本**自己定位仓库根目录**（`import.meta.url`），clone 到哪儿都能跑。
- 临时目录在 `.tmp-check/`（已被 `.gitignore` 排除），跑完自己删。
- `check-render.mjs` 用 `config.root` 把主机半挂到临时目录，
  **绝不会碰你真实的 `progress/`**。
- 想验证某个检查是不是真的有用：故意把对应的问题改回去，看它报不报。
  「没验证过的回归测试等于没有测试」——这条是踩过坑才写下的。
